# KAB6ANbl ESPORTS — установка на REG.RU

## Быстрая установка готовой сборки из GitHub

Для виртуального хостинга нужны Git, стандартные команды shell и PHP 8.1+ с расширением cURL. Node.js, npm и sudo на сервере не нужны: готовая сборка хранится в `reg-ru-site/` в этом репозитории. Сборка для REG.RU обращается к Supabase через `supabase-proxy.php` на домене сайта; скрипт разрешает только чтение используемых таблиц и вызов существующей Edge Function `site-admin`. Данные и проверка сессии остаются в Supabase.

Выполните в shell REG.RU:

```bash
cd "$HOME" && W=$(mktemp -d "${TMPDIR:-/tmp}/site-installer.XXXXXXXX") && git clone --depth 1 --branch main https://github.com/wwdewew1111-ctrl/SiteVSservice.git "$W/repo" && sh "$W/repo/install-reg-ru.sh"
```

По умолчанию используется `$HOME/www/kabanyesports.online`. Если панель REG.RU указывает другую физическую папку сайта, передайте её последним аргументом, например:

```bash
sh "$W/repo/install-reg-ru.sh" "$HOME/www/другой-домен"
```

Установщик выводит содержимое папки и запрашивает `YES`. Перед копированием он сохраняет её содержимое в отдельную папку `$HOME/site-backup-...`, путь выводится в консоль. Совпадающие имена будут перезаписаны, остальные файлы не удаляются. Убедитесь, что свободного места достаточно. Не запускайте установщик для неверной папки и проверьте `.htaccess` перед заменой, если он содержит важные настройки. По умолчанию устанавливается `main`; чтобы закрепить конкретный тег, запустите скрипт с переменной окружения `SITE_REF`, например `SITE_REF=1.0.16 sh "$W/repo/install-reg-ru.sh"`.

Скопируется только содержимое `reg-ru-site/`, включая `.htaccess`; исходники, `.git`, `.env` и `node_modules` в каталог сайта не копируются. После установки проверьте главную страницу и прямой переход на `/admin`. Для SPA-маршрутов Apache должен разрешать `.htaccess` и `mod_rewrite`. HTTPS требует действующего SSL-сертификата.

## Обновление готовой сборки для GitHub

Если меняете исходный код, соберите новую версию на компьютере с Node.js 20.19+ или 22.12+ и отправьте изменённые файлы `reg-ru-site/` в GitHub. Регулярная сборка на сервере не выполняется автоматически.

Для сборки необходимы переменные окружения:

```text
VITE_SUPABASE_URL=https://dydsgyjwjbrcymkvzrji.supabase.co
VITE_SUPABASE_ANON_KEY=<Supabase publishable public key>
VITE_SUPABASE_PROXY=true
```

Выполните `npm ci`, `npm run typecheck`, `npm run build`, затем замените содержимое `reg-ru-site/` содержимым `dist/`, включая скрытый `.htaccess`. Vite встраивает `VITE_*` в публичные файлы, поэтому используйте только публичный ключ; никогда не используйте `service_role`, Supabase secret key или FACEIT-ключ. Если меняются URL или публичный ключ Supabase, сборку также нужно пересоздать.

Существующий проект Supabase и его данные не изменяются. Серверные функции FACEIT/admin по-прежнему работают в Supabase Edge Functions; хостинг только пересылает запросы. В режиме PHP-прокси матчи на открытой публичной странице обновляются опросом каждые 30 секунд вместо WebSocket; в админке изменения, внесённые в других сессиях, отображаются после обновления страницы. Без `VITE_SUPABASE_PROXY=true` сайт подключается к Supabase напрямую и использует Realtime.
